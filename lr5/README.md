# Cinema-salesperson-s-workplace

Предметна область: **робоче місце касира кінотеатру**.

## Лабораторна робота №5 — рефакторинг із паттернами GoF

Це рефакторинг коду ЛР №4 (знижки, способи оплати), а не новий проєкт.
Файли ЛР №4 (`DiscountStrategy`, `PaymentMethod`, `AbstractPayment`, `CashPayment` тощо) **не змінювалися**.

### Рівень 1. Factory (Simple Factory)

**Проблема до рефакторингу.** Клієнтський код створював способи оплати та знижки напряму:
```java
PaymentMethod[] methods = { new CashPayment(), new CardPayment(), new OnlinePayment() };
DiscountStrategy s = new PercentDiscount("Студентська знижка 20%", 20);
```
Щоб додати новий тип, треба було шукати й правити кожне місце з `new`; клієнт знав про всі конкретні класи.

**Після.** `PaymentFactory.create("card")` та `DiscountFactory.create("student")` — єдине місце створення.
Додати новий тип = один новий клас + один рядок у `switch` фабрики; клієнтський код не змінюється.
Невідомий код → `IllegalArgumentException` (помилка видна одразу, а не "тихий" `null`).

### Рівень 2. Observer

**Ситуація.** Зміна статусу замовлення (`NEW → PAID → CANCELLED`) має сповіщати кілька модулів.

| Роль | Клас |
|------|------|
| Subject | `Order` (список підписників, `addObserver`, `removeObserver`, `changeStatus`) |
| Observer (інтерфейс) | `OrderObserver` |
| Спостерігачі | `OrderLogger` (журнал), `SmsNotifier` (сповіщення клієнта), `SalesReport` (виручка) |

Новий спостерігач = новий клас + `order.addObserver(...)`; код `Order` не змінюється.
`FaultyObserver` показує: виняток одного спостерігача перехоплюється в `Order` і не ламає решту.

### Рівень 3. Adapter

`LegacyBankGateway` — "сторонній" шлюз (змінювати не можна): суми в копійках (`int`), методи `makeTransaction` / `calcCommissionKop`, результат — числовий код.
`BankGatewayPaymentAdapter` реалізує наш `PaymentMethod` і перекладає гривні → копійки, назви методів, код результату → текст. Шлюз тримається як поле (композиція).

**Чому Adapter, а не переписування шлюзу:** шлюз — зовнішня бібліотека, змінити її не можна; адаптер ізолює несумісність в одному класі, а решта програми працює з `PaymentMethod`.

### Запуск (Java 25)
```bash
cd lr5
java lr5cinema.java
```
Усі `.java` файли мають лежати в одній папці.

### Як перевірено, що попередня функціональність не зламана
Класи ЛР №4 не змінювалися; результати розрахунків знижок і оплат у `lr5cinema.java` збігаються з виводом `lr4cinema.java` для тих самих даних (6 квитків × 150 грн, студентська знижка → 720 грн).

### Місце, де паттерн свідомо не застосовано
Клас `Order` можна було б створювати через фабрику, але конструктор простий і створюється в одному місці — це був би over-engineering.
